# Модуль «Анализы»

## Что включено сейчас (этап 4)

- Модель `analysis_records` (запись об анализе: дата, лаборатория, кто направил, заметки) + `analysis_values` (отдельные показатели в записи).
- Справочник норм [`backend/app/data/analysis_norms.json`](../backend/app/data/analysis_norms.json) — 52 параметра по 7 категориям: ОАК, биохимия, липиды, гормоны щитовидной, ОАМ, витамины/минералы, углеводный обмен, гормоны, онкомаркеры, электролиты.
- Автоматический расчёт `is_abnormal` + `abnormal_type` (`low | high | normal | unknown`) при создании/правке.
- Авто-подстановка `reference_min/max` из справочника по полу + возрасту пользователя.
- Графики динамики одного показателя (Chart.js + plugin annotation для зелёной зоны нормы).
- Поиск показателей в справочнике с автокомплитом и кэшем Redis (1 час).

## Как добавить новый параметр

1. Открыть `backend/app/data/analysis_norms.json`.
2. Добавить новый ключ:
   ```json
   "my_new_param": {
     "name_ru": "Моё название",
     "name_en": "My name",
     "unit": "ед",
     "category": "Биохимия",
     "synonyms": ["alias1", "alias2"],
     "norms": [
       {"gender": "any", "age_from": 0, "age_to": 200, "min": 1.0, "max": 9.0}
     ]
   }
   ```
3. Перезапустить backend (`docker compose restart backend`). Справочник кэшируется через `@lru_cache(maxsize=1)`.
4. Очистить Redis-кэш поиска: `docker compose exec redis redis-cli FLUSHDB` (опционально — записи устареют сами через час).

Поле `gender` принимает `male`, `female`, `any`. Точное совпадение пола имеет приоритет над `any`. Диапазон `age_from..age_to` — включительный.

## Как работает расчёт `is_abnormal`

Логика в [`app/utils/analysis_norm_calc.py`](../backend/app/utils/analysis_norm_calc.py):

1. Парсер `parse_number`:
   - запятая → точка (русский формат);
   - префиксы `<`, `>`, `≤`, `≥` обрезаются — берётся числовая часть как приближение;
   - текст («положительный») → `ValueParseError`.
2. `calculate_abnormal(value, ref_min, ref_max)`:
   - Если value не распарсилось → `UNKNOWN`.
   - Если оба референса `None` → `UNKNOWN` (нечем сравнивать).
   - Меньше `ref_min` → `LOW`.
   - Больше `ref_max` → `HIGH`.
   - Иначе → `NORMAL`.

Цвета на UI:
- 🟢 зелёный — `NORMAL` и не у границы.
- 🟡 оранжевый — `NORMAL`, но в пределах ±5% от границы (близко к норме, стоит наблюдать).
- 🔴 красный — `LOW` или `HIGH`.
- ⚪ серый — `UNKNOWN`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/analyses?date_from=&date_to=&only_abnormal=` | Список с фильтрами |
| POST | `/api/v1/analyses` | Создать запись с массивом values |
| GET | `/api/v1/analyses/{id}` | Полная запись |
| PATCH | `/api/v1/analyses/{id}` | Обновить метаданные (lab, notes, date) |
| DELETE | `/api/v1/analyses/{id}` | Удалить (cascade values) |
| PATCH | `/api/v1/analyses/values/{value_id}` | Обновить отдельное значение (пересчитает abnormal) |
| GET | `/api/v1/analyses/parameters/{code}/history` | История параметра для графика |
| GET | `/api/v1/dictionaries/analysis-parameters?search=` | Поиск по справочнику |
| GET | `/api/v1/dictionaries/analysis-parameters/{code}?gender=&age=` | Детали + норма для контекста пользователя |

Все за `Depends(get_current_user)`.
