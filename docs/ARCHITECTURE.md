# Архитектура МедАрхива

> Этот документ описывает **целевую** архитектуру всего проекта. Часть
> сервисов появляется на следующих этапах (пометки «с этапа N»).

## Высокоуровневая схема

```
                              ┌────────────────────────┐
                              │       Браузер          │
                              └───────────┬────────────┘
                                          │ HTTPS (этап 12) / HTTP (dev)
                                          ▼
                              ┌────────────────────────┐
                              │        Nginx           │  reverse proxy + TLS
                              └─────┬────────────┬─────┘
                                    │            │
                /api/*, /docs       │            │   /
                                    ▼            ▼
                       ┌──────────────────┐  ┌──────────────────┐
                       │  Backend (FastAPI)│ │ Frontend (Vite)  │
                       └─────┬──────┬─────┘  └──────────────────┘
                             │      │
                ┌────────────┘      └──────────┐
                ▼                              ▼
        ┌────────────┐                  ┌──────────────┐
        │  MariaDB   │                  │    Redis     │  кэш / брокер очередей
        └────────────┘                  └──────────────┘
                                                ▲
                                                │ (с этапа 6)
                                        ┌───────┴────────┐
                                        │ Celery worker  │
                                        │ Celery beat    │
                                        └────────────────┘

   Сервисы, добавляемые позже:
   • redis_keys (без persistence)  — этап 7, хранит мастер-ключи шифрования
   • telegram_bot                  — этап 6
   • certbot                       — этап 12
```

## Слои backend

```
api/         HTTP-обработчики (FastAPI routers, Pydantic-валидация)
services/    Бизнес-логика. Здесь происходит шифрование и вызовы внешних API.
models/      SQLAlchemy 2.0 ORM-модели.
schemas/     Pydantic-схемы request/response.
tasks/       Celery-задачи (с этапа 6).
utils/       Вспомогательные функции (KDF, генераторы кодов).
data/        Справочные JSON (нормы анализов и т.п.).
```

**Жёсткое правило:** API никогда не работает с моделями БД напрямую — только
через services. Это упрощает тесты и подмену реализаций (например,
identity-шифрование → AES на этапе 7).

## Изоляция данных пользователей

- В каждом SQL-запросе — `WHERE user_id = ?`.
- Все методы services принимают `user_id` и фильтруют по нему.
- В тестах проверяется, что пользователь A не читает данные пользователя B.
